# برنامه دانشگاه — معماری بدون دیتابیس

این نسخه عمداً هیچ دیتابیس یا سرویس خارجی ندارد.

## راه‌اندازی پروژه (GitHub Pages)

1. در GitHub یک مخزن (repository) بساز. برای GitHub Pages رایگان، مخزن باید **Public** باشد.
2. همه‌ی فایل‌های پروژه را با **همان ساختار پوشه‌ها** آپلود کن (`Add file ← Upload files`؛ پوشه‌های `users` و `fonts` را هم بکش و رها کن). فایل‌ها باید در ریشه‌ی مخزن باشند، نه داخل یک پوشه‌ی اضافه.
3. به `Settings ← Pages` برو. در `Source` گزینه‌ی **Deploy from a branch** را بزن، شاخه‌ی `main` و پوشه‌ی `/ (root)` را انتخاب و Save کن.
4. بعد از یکی دو دقیقه سایت روی `https://USERNAME.github.io/REPO/` باز می‌شود. صفحه‌ی ورود همان `index.html` است و ابزار مدیر در `editor.html` و `fonts.html`.
5. هر تغییر بعدی (کاربر جدید، ویرایش برنامه، فونت) را فقط با آپلود/جایگزین کردن فایل و commit انجام بده. بعد از commit ممکن است تا حدود یک دقیقه طول بکشد تا سایت به‌روز شود.

**تست روی کامپیوتر:** با دابل‌کلیک روی `index.html` کار نمی‌کند (چون فایل‌ها با `fetch` خوانده می‌شوند). در پوشه‌ی پروژه این را بزن و `http://localhost:8000` را باز کن:

```bash
python -m http.server 8000
```

## ساختار

```text
/
├── index.html          ← انتخاب کاربر
├── schedule.html       ← نمایش برنامه
├── editor.html         ← ساخت/ویرایش فایل JSON
├── fonts.html          ← مدیریت فونت‌ها (ابزار مدیر)
├── common.js           ← توابع مشترک (هفته فرد/زوج، تداخل، تبدیل داده)
├── fonts.js            ← انتخاب فونت توسط کاربر
├── styles.css
├── icon.svg
├── fonts/
│   ├── index.json      ← فهرست فونت‌ها
│   └── (فایل‌های woff2 / ttf ...)
└── users/
    ├── index.json      ← لیست کاربران
    ├── a.json          ← برنامه کاربر a
    └── ...
```

## اضافه کردن کاربر جدید

1. `editor.html` را باز کن.
2. نام کاربری مثلاً `ali` و نام نمایشی را وارد کن.
3. کلاس‌ها و ترم‌ها را وارد کن.
4. «ذخیره و دریافت فایل» را بزن.
5. فایل `ali.json` را داخل `users/` قرار بده.
6. در `users/index.json` یک ورودی اضافه کن:

```json
{
  "username": "ali",
  "displayName": "علی",
  "file": "users/ali.json"
}
```

7. تغییرات را در GitHub commit کن.

بعد کاربر با وارد کردن شناسه‌اش (`ali`) در صفحه اصلی وارد برنامه‌ی خودش می‌شود و سایت `users/ali.json` را می‌خواند. فهرست همه‌ی کاربران نمایش داده نمی‌شود؛ فقط تعداد کاربران دیده می‌شود.

## دیدن همه‌ی کاربران و فراموشی شناسه

- **مدیر:** در فیلد شناسه‌ی صفحه‌ی اول عبارت `@sign_all` را بنویس تا فهرست همه‌ی شناسه‌ها (با نام نمایشی) نشان داده شود.
- **فراموشی شناسه:** دکمه‌ی «شناسه‌ام را فراموش کرده‌ام» یک کادر باز می‌کند. کاربر هر بخشِ پشت‌سرهم از شناسه‌اش را (حداقل ۳ حرف یا رقم) می‌نویسد؛ شناسه‌هایی که آن بخش را دارند و بعد شناسه‌های شبیه (حداقل ۶۰٪ از آن بخش مشترک) تا ۱۰ مورد نمایش داده می‌شوند. فقط خود شناسه نشان داده می‌شود و با زدن روی آن وارد برنامه می‌شود.
- هر دو قابلیت سمت مرورگرند و بدون دیتابیس از روی `users/index.json` کار می‌کنند؛ پس `@sign_all` رمز نیست و هر کس کد سایت را بخواند می‌تواند آن را پیدا کند.

## ویرایش برنامه موجود

می‌توانی فایل `a.json` را در `editor.html` وارد کنی، تغییرات را بدهی و دوباره فایل را دانلود کنی. سپس فایل قبلی را در GitHub جایگزین کن.

## ساختار فایل کاربر (نسخه ۲)

هر درس فقط یک بار ثبت می‌شود و جلسه‌های هفتگی‌اش داخل `sessions` می‌آیند:

```json
{
  "version": 2,
  "username": "a",
  "displayName": "Abolfazl",
  "activeTermId": "t1",
  "terms": [{
    "id": "t1",
    "name": "نیمسال اول",
    "weekAnchor": { "date": "2026-10-03", "parity": "even" },
    "courses": [{
      "id": "k1", "name": "شبکه‌های کامپیوتری", "teacher": "...", "faculty": "...",
      "units": 3, "color": "#0b8b68",
      "sessions": [
        { "id": "k1_s1", "day": "sat", "start": "15:00", "end": "17:00", "room": "۲۱۵", "weeks": "all" },
        { "id": "k1_s2", "day": "sun", "start": "15:00", "end": "17:00", "room": "۲۱۵", "weeks": "odd" }
      ]
    }]
  }]
}
```

- `weeks` یکی از `all` (هر هفته)، `odd` (فقط هفته فرد) یا `even` (فقط هفته زوج) است.
- فایل‌های قدیمی (نسخه ۱ با `classes`) هنگام باز شدن در سایت و در ادیتور خودکار به این ساختار تبدیل می‌شوند.

## ترم‌ها

آخرین ترم فایل همیشه «ترم فعال» است و به‌صورت پیش‌فرض نمایش داده می‌شود؛ پس ترم جدید را باید آخر اضافه کنی. اگر بیش از یک ترم باشد، نوار انتخاب ترم بالای صفحه می‌آید و در تب «ترم‌ها» جزئیات درس‌ها و جلسه‌های هر ترم دیده می‌شود.

## ساعت‌ها و رنگ‌ها

همه‌ی ساعت‌ها ۲۴ ساعته‌اند (۷ عصر = ۱۹:۰۰) و در ادیتور با انتخاب ساعت و دقیقه وارد می‌شوند، مستقل از تنظیم ۱۲/۲۴ ساعته‌ی دستگاه. جدول هفته ثابت از ۰۸:۰۰ تا ۱۹:۰۰ است (`DAY_START` و `DAY_END` در `common.js`) و ادیتور فقط جلسه‌های داخل این بازه را می‌پذیرد. برای هر درس ۱۲ رنگ در دسترس است.

## فونت‌ها

سایت عمداً هیچ درخواست خارجی ندارد. فونت‌ها را خودت آپلود می‌کنی و هر کاربر با دکمه‌ی **Aa** بالای صفحه یکی را انتخاب می‌کند (انتخاب هر کاربر روی دستگاه خودش ذخیره می‌شود).

1. `fonts.html` را باز کن (از لینک «فونت‌ها» در ادیتور).
2. فایل‌های فونت (`woff2` بهتر است) را انتخاب کن و برای هرکدام نام نمایشی بنویس.
3. با دکمه‌ی «دریافت فایل با نام درست» فایل‌ها را بگیر و همراه `index.json` خروجی داخل پوشه‌ی `fonts/` مخزن GitHub بگذار.
4. commit کن؛ فونت‌ها در فهرست **Aa** ظاهر می‌شوند.

اگر فونت انتخاب‌شده لود نشود، سایت بی‌صدا به فونت دستگاه برمی‌گردد.

## هفته فرد و زوج

در `editor.html` برای هر ترم یک **تاریخ مبنا** و **نوع هفته‌ی آن تاریخ** (فرد/زوج) وارد کن. سایت از روی ساعت و تاریخ دستگاه خودش هفته‌ی فعلی را حساب می‌کند و هر هفته به‌صورت خودکار عوض می‌شود؛ نیازی به اینترنت یا ویرایش دوباره نیست. هفته‌ها از شنبه شروع می‌شوند. روز و نوع هفته در بالای صفحه نمایش داده می‌شود.

## صفحه «امروز»

- بالا: کلاسی که در حال برگزاری است (یا اگر کلاسی در جریان نیست، کلاس بعدی امروز) و زیرش کلاس بعدی.
- اگر امروز تعطیل است یا کلاس‌ها تمام شده‌اند، فقط کلاس بعدی (فردا یا روزهای بعد) نمایش داده می‌شود و کلاس‌های تمام‌شده نشان داده نمی‌شوند.
- صفحه هر ۳۰ ثانیه خودش به‌روز می‌شود.

## یکتا بودن username

ادیتور قبل از ساخت فایل، `users/index.json` سایت را می‌خواند و اگر username قبلاً وجود داشته باشد (بدون حساسیت به حروف بزرگ و کوچک) ذخیره را رد می‌کند. فقط وقتی فایلِ همان کاربر را با «ویرایش فایل موجود» باز کرده باشی، همان username مجاز است. اگر ادیتور از طریق سرور باز نشده باشد، بررسی ممکن نیست و از تو تأیید می‌گیرد.

## هشدار تداخل

اگر دو جلسه در یک روز هم‌زمان باشند و در یک نوع هفته بیفتند (مثلاً یکی فرد و دیگری زوج تداخل حساب نمی‌شود)، هم در `editor.html` و هم در صفحه برنامه هشدار «تداخل زمانی» نمایش داده می‌شود.

## نکته مهم

این مدل عمداً «بدون دیتابیس» است. بنابراین هر تغییری که کاربران در `editor.html` می‌دهند فقط یک فایل خروجی می‌سازد؛ **آن‌ها مستقیماً نمی‌توانند سایت GitHub را تغییر دهند.** فقط کسی که دسترسی به repository دارد می‌تواند فایل JSON را آپلود/جایگزین کند.

این یعنی نقش‌ها دقیقاً مطابق ایده تو هستند:
- کاربران: ساخت/ویرایش فایل خودشان و تحویل آن به مدیر
- مدیر: قرار دادن فایل‌ها در `users/` و تغییر `users/index.json`
- سایت: فقط فایل‌های منتشرشده را می‌خواند.

**حریم خصوصی:** چون سایت بدون دیتابیس است، فایل‌های `users/index.json` و `users/<id>.json` برای هر کسی که آدرسشان را بداند قابل خواندن است. شناسه (id) رمز عبور نیست؛ برنامه‌ی کلاسی را در آن ذخیره نکن که نباید دیده شود.
