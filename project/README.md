# برنامه دانشگاه — معماری بدون دیتابیس

این نسخه عمداً هیچ دیتابیس یا سرویس خارجی ندارد.

## ساختار

```text
/
├── index.html          ← انتخاب کاربر
├── schedule.html       ← نمایش برنامه
├── editor.html         ← ساخت/ویرایش فایل JSON
└── users/
    ├── index.json      ← لیست کاربران
    ├── a.json          ← برنامه کاربر a
    └── ...
```

## اضافه کردن کاربر جدید

1. `editor.html` را باز کن.
2. نام کاربری مثلاً `ali` و نام نمایشی را وارد کن.
3. کلاس‌ها و ترم‌ها را وارد کن.
4. «ذخیره و دریافت فایل» را بزن.
5. فایل `ali.json` را داخل `users/` قرار بده.
6. در `users/index.json` یک ورودی اضافه کن:

```json
{
  "username": "ali",
  "displayName": "علی",
  "file": "users/ali.json"
}
```

7. تغییرات را در GitHub commit کن.

بعد کاربر در صفحه اصلی دیده می‌شود و با انتخاب او، سایت `users/ali.json` را می‌خواند.

## ویرایش برنامه موجود

می‌توانی فایل `a.json` را در `editor.html` وارد کنی، تغییرات را بدهی و دوباره فایل را دانلود کنی. سپس فایل قبلی را در GitHub جایگزین کن.

## اجرای محلی

سایت فایل‌های JSON را با `fetch` می‌خواند، پس با دابل‌کلیک روی `index.html` کار نمی‌کند. برای تست محلی در پوشه پروژه این دستور را بزن و `http://localhost:8000` را باز کن:

```bash
python -m http.server 8000
```

روی GitHub Pages مشکلی نیست.

## هشدار تداخل

اگر دو کلاس در یک روز هم‌زمان باشند، هم در `editor.html` و هم در صفحه برنامه هشدار «تداخل زمانی» نمایش داده می‌شود.

## نکته مهم

این مدل عمداً «بدون دیتابیس» است. بنابراین هر تغییری که کاربران در `editor.html` می‌دهند فقط یک فایل خروجی می‌سازد؛ **آن‌ها مستقیماً نمی‌توانند سایت GitHub را تغییر دهند.** فقط کسی که دسترسی به repository دارد می‌تواند فایل JSON را آپلود/جایگزین کند.

این یعنی نقش‌ها دقیقاً مطابق ایده تو هستند:
- کاربران: ساخت/ویرایش فایل خودشان و تحویل آن به مدیر
- مدیر: قرار دادن فایل‌ها در `users/` و تغییر `users/index.json`
- سایت: فقط فایل‌های منتشرشده را می‌خواند.
